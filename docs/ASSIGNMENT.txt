Data model (starting point — extend if needed)
CREATE TABLE products (
id SERIAL PRIMARY KEY,
sku TEXT NOT NULL UNIQUE,
name TEXT NOT NULL,
price INTEGER NOT NULL CHECK (price >= 0), stock INTEGER NOT NULL DEFAULT 0 CHECK (stock >= 0),
is_active BOOLEAN NOT NULL DEFAULT TRUE,
created_at TIMESTAMPTZ NOT NULL DEFAULT now()
-- IDR, integer: no float money
);
CREATE TABLE stock_movements (

id SERIAL PRIMARY KEY,
product_id INTEGER NOT NULL REFERENCES products(id),
type TEXT NOT NULL CHECK (type IN ('in', 'out')),
qty INTEGER NOT NULL CHECK (qty > 0),
note TEXT,
created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE TABLE sales_orders (
id SERIAL PRIMARY KEY,
customer TEXT NOT NULL,
status TEXT NOT NULL DEFAULT 'CREATED' CHECK (status IN ('CREATED','CANCELLED')),
total INTEGER NOT NULL,
created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
cancelled_at TIMESTAMPTZ
);
CREATE TABLE sales_order_items (
id SERIAL PRIMARY KEY,
order_id INTEGER NOT NULL REFERENCES sales_orders(id),
sku TEXT NOT NULL REFERENCES products(sku),
qty INTEGER NOT NULL CHECK (qty > 0),
unit_price INTEGER NOT NULL
);

Order creation rules (the core of the test)

1. Validate everything before writing: unknown sku, qty <= 0, duplicate skus in one order, empty items →
   400 with clear messages.
2. unit_price comes from the products table — the client never supplies prices. total is computed
   server-side.
3. 4. 5. Stock decrement for ALL items happens atomically in one transaction: either the whole order exists or
         nothing changed.
         If any item is insufficient → 409
         {"error":{"code":"INSUFFICIENT_STOCK","sku":"...","available":n}} and no stock may have
         changed.
         Under concurrent orders for the same SKU, stock may never go negative. Guard inside the UPDATE (or
         row locks) — never SELECT-then-UPDATE.
